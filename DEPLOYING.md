# Deploying VibeSkool

The React app runs on **Vercel**. The Django API, with its live class updates,
runs on **Render**, with Redis next to it. The database and uploaded files are
on **Supabase**. Work through the sections in order; each one says what to copy
where.

You'll need accounts on Render, Supabase (already set up), Resend (email),
RapidAPI (code runner) and Sentry (error reports). All have free tiers except
the Render web service: about $7 a month on Starter, which doesn't sleep.

---

## 1. Database: apply the new migrations

The new code adds tables and columns: tutor requests, sign-out on password
change, and skill check attempts. Run this once from `backend-django/`, with
`DATABASE_URL` in `.env` pointing at Supabase:

```powershell
.venv\Scripts\python manage.py migrate
```

After the first deploy, Render runs this for you before every release.

## 2. Supabase Storage for uploads

Render's disk is wiped on every deploy, so avatars and project images go to a
storage bucket.

1. Supabase → **Storage** → **New bucket**: name it `media` and turn on **Public bucket**.
2. **Project settings → Storage → S3 connection**: copy the **Endpoint** and the
   **Region**, then **New access key** and copy both keys.
3. You'll paste these into Render (section 6) as:

| Render variable | Value |
| --- | --- |
| `STORAGE_BUCKET` | `media` |
| `STORAGE_ENDPOINT` | `https://<project>.storage.supabase.co/storage/v1/s3` |
| `STORAGE_REGION` | e.g. `eu-west-1` |
| `STORAGE_ACCESS_KEY` / `STORAGE_SECRET_KEY` | the access key pair |
| `STORAGE_PUBLIC_URL` | `https://<project>.supabase.co/storage/v1/object/public/media` |

4. To move files you already uploaded while developing (in `backend-django/media`),
   put the same five variables in your local `.env`, then run:

```powershell
.venv\Scripts\python manage.py move_media_to_storage --dry-run
```

```powershell
.venv\Scripts\python manage.py move_media_to_storage
```

## 3. Email (password resets, tutor requests)

1. Sign up at [resend.com](https://resend.com) and add your domain under
   **Domains**. Add the DNS records it shows you, and wait for "Verified".
2. **API Keys → Create** (sending access only).
3. Render variables: `EMAIL_HOST=smtp.resend.com`, `EMAIL_HOST_USER=resend`,
   `EMAIL_HOST_PASSWORD=<the API key>`, `DEFAULT_FROM_EMAIL=VibeSkool <hello@yourdomain.com>`.

Any other SMTP provider works the same way. Without a domain you can only send
to your own address, so reset emails won't reach students.

New tutor requests are emailed to every staff account. Set
`TUTOR_REQUEST_EMAILS=you@example.com` to choose who gets them instead.

## 4. Code runner (Judge0 on RapidAPI)

1. Open [Judge0 CE on RapidAPI](https://rapidapi.com/judge0-official/api/judge0-ce)
   and subscribe to a plan (Basic is free, about 50 runs a day).
2. Copy your **X-RapidAPI-Key**. That's `JUDGE0_KEY` on Render.
3. Each exercise check is a single run, however many tests it has. When the
   daily quota runs out, students see "Couldn't run your code right now"
   until it resets. Upgrade the plan once classes are busy.

The defaults are language 93 (Node.js 18) and 92 (Python 3.11). If runs fail
with an unknown language, call `GET /languages` in RapidAPI's playground and
set `JUDGE0_JS_ID` / `JUDGE0_PYTHON_ID` to the ids it lists.

## 5. Error reports (Sentry)

1. At [sentry.io](https://sentry.io), create two projects: **Django** and **React**.
2. Copy each project's DSN: the Django one goes in `SENTRY_DSN` on Render, the React
   one in `VITE_SENTRY_DSN` on Vercel.

Neither sends personal data (no IP addresses, no form contents).

## 6. The API on Render

1. Push this branch to GitHub.
2. Render → **New → Blueprint** → pick the repo. It reads `render.yaml`
   and sets up `vibeskool-api` (Starter, Frankfurt, the closest region to the
   Supabase database in Ireland) and `vibeskool-redis`.
3. Fill in the values it asks for:
   - `DATABASE_URL`: Supabase → **Connect → Session pooler** (port 5432), with your database password.
   - `FRONTEND_URL`: your Vercel address, e.g. `https://vibeskool.vercel.app`.
     It sets which site may call the API and open live-update sockets, and where email links point.
   - `GOOGLE_CLIENT_ID`, `GEMINI_API_KEY`, `JUDGE0_KEY`, the `STORAGE_*`, `EMAIL_*` and
     `SENTRY_DSN` values from the sections above.
   - `ADMIN_PATH`: optional; something like `staff-7f3k` moves the admin off `/admin/`.

   `DJANGO_SECRET_KEY` and `JWT_SECRET` are generated by Render. Don't reuse the
   ones from your `.env`: the server refuses to start with short or example secrets.
4. When the deploy is green, open `https://<your-service>.onrender.com/api/health`.
   It should answer `{"status": "ok"}`.
5. Make your admin account. In the service, open **Shell** and run:

```bash
python manage.py createsuperuser
```

The lessons and the skill check questions are already in the Supabase
database. For a fresh database, also run `python manage.py seed_content` in that shell.

## 7. The React app on Vercel

Vercel project → **Settings → Environment Variables** (Production):

| Variable | Value |
| --- | --- |
| `VITE_API_URL` | `https://<your-service>.onrender.com` |
| `VITE_GOOGLE_CLIENT_ID` | same client id as on Render |
| `VITE_SENTRY_DSN` | the React DSN (optional) |

Then **Deployments → Redeploy**: Vite builds these values into the app, so
changing them needs a new build.

In Google Cloud Console → **Credentials** → your OAuth client, add the Vercel
address under **Authorized JavaScript origins**.

`frontend/vercel.json` sets the security headers. Pages can't be framed by
other sites, plugins are blocked and the browser features the app doesn't use are off.

## 8. Backups

Supabase's free plan keeps no backups you can download. A GitHub Action
(`.github/workflows/backup.yml`) dumps the database every night, encrypts it,
and keeps 30 days of copies.

1. GitHub → repo **Settings → Secrets and variables → Actions → New repository secret**:
   - `BACKUP_DATABASE_URL`: the same Session pooler address as `DATABASE_URL`.
   - `BACKUP_PASSPHRASE`: a long random passphrase. Store it in your password
     manager; without it a backup can't be opened.
2. **Actions → Database backup → Run workflow** to check it works. The run
   should end with an artifact named `vibeskool-db-<date>`.

**To restore a backup:** download the artifact and unzip it, then:

```bash
gpg --decrypt vibeskool-YYYY-MM-DD.pgc.gpg > dump.pgc
pg_restore --clean --if-exists --no-owner --dbname "<DATABASE_URL>" dump.pgc
```

Restore into a new Supabase project first if you only need to look at old
data. `--clean` replaces what's in the target database.

## 9. Watch it

- **Uptime:** add a free monitor at [Better Stack](https://betterstack.com) or
  [UptimeRobot](https://uptimerobot.com) on `https://<your-service>.onrender.com/api/health`.
  It returns 503 when the database can't be reached.
- **Errors:** Sentry emails you the first time each new error happens.
- **Logs and metrics:** Render → the service → **Logs** / **Metrics**.

## 10. Check it works

- [ ] Sign up as a student, log out, use **Forgot password?**, and get the email.
- [ ] Sign up and ask to teach. The admin email arrives. Approve in the admin
      (Users → filter "Tutor status" → select → **Approve as tutors**). The
      tutor email arrives, and **Teaching** appears after a refresh.
- [ ] Upload an avatar; its address starts with your Supabase storage URL.
- [ ] Submit a coding exercise; it's checked (one Judge0 run).
- [ ] Take a skill check; the result is saved to your progress.
- [ ] Open a class in two browsers; a post in one shows up live in the other.

## Later

- **Your own domain:** point it at Vercel (app) and Render (`api.` subdomain).
  Update `FRONTEND_URL`, `VITE_API_URL` and the Google origins. Then set
  `SECURE_HSTS_INCLUDE_SUBDOMAINS=1` on Render.
- **More traffic:** raise the Render plan or instance count; Redis already
  shares live updates and rate limits across instances. Raise `DB_POOL_SIZE` only
  while the total stays under Supabase's connection limit (15 on the session pooler).
